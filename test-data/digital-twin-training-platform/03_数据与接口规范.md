# 数字孪生实训平台数据与接口规范

## 设备与点位编码

设备编码采用“类型-序号”格式，一期固定为 CNC-01、ROBOT-02、LINE-03。点位标识采用 `<设备编码>.<业务名称>`，例如 `CNC-01.spindle_rpm`、`ROBOT-02.joint_1_angle`、`LINE-03.conveyor_running`。点位包含名称、数据类型、单位、读写属性、有效范围、采样周期和质量状态。

## OPC UA 接入

OPC UA 节点统一位于 `Objects/TrainingPlatform/<设备编码>/Variables`。连接启用证书认证与 `Basic256Sha256` 安全策略，禁止匿名访问。默认采样周期为 500ms，可在 200ms 至 5000ms 之间配置。客户端断线后采用指数退避重连，并把断线期间数据质量标记为 `bad`。

## MQTT 主题

遥测主题格式为 `dts/edu/v1/<设备编码>/telemetry`，状态主题为 `dts/edu/v1/<设备编码>/state`，告警主题为 `dts/edu/v1/alert`。遥测使用 QoS 1，不使用保留消息；设备在线状态可以使用保留消息。消息必须包含时间戳、设备、点位、值、质量和来源。

示例：

```json
{
  "ts": 1787613600000,
  "device": "CNC-01",
  "point": "spindle_rpm",
  "value": 1250.5,
  "quality": "good",
  "source": "opcua"
}
```

## 告警与时序数据

告警等级分为 `info`、`warning`、`error` 和 `critical`。告警记录包含告警编号、设备、等级、代码、说明、触发时间、确认人和恢复时间。原始时序数据保留 90 天，一分钟聚合数据保留 365 天；操作日志保留 180 天。

## 业务接口约定

内部接口基路径为 `/api/v1`。请求必须包含请求追踪编号和 ISO 8601 时间戳。响应统一使用 `code`、`message`、`data` 字段。常用错误码包括：1001 设备未注册、1002 点位不存在、2001 MQTT 连接超时、2002 OPC UA 节点不可达、4001 并发超限、5001 数据校验失败。

## 数据质量与安全

设备到平台展示的端到端延迟目标不超过 500ms，单日数据丢失率低于 0.1%。同一点位经 OPC UA 与 MQTT 两条链路传输时，布尔值必须一致，浮点值偏差不超过 0.5%。所有通信启用 TLS 1.2 以上版本，凭证禁止明文存储，日志不得记录令牌或完整敏感载荷。设备接入采用白名单和最小权限原则。
